## 2026-08-23 — `W5`: a PRD lost to a harness failure is rebuilt from the session transcript, not re-brainstormed

The opencode session for `campaign-filter-atl-earned` (`ses_fd2406744ffeenffkjjVfQuPok`,
2026-08-23 15:32–16:50) completed all three brainstorming rounds — eleven questions asked and
answered — and then aborted every one of its twelve `write` calls. Branches existed on all three
repos; the PRD did not. Nothing on disk recorded that the decisions had been made.

**Decision:** rebuild from the transcript rather than re-run the brainstorming. opencode persists
full session state at `~/.local/share/opencode/opencode.db` (SQLite: `session`, `message`, `part`).
The `part` rows for `tool: "question"` carry both the options offered **and** the user's recorded
answers, so the decisions are recoverable verbatim — re-asking would have risked different answers
to the same questions and produced a second, divergent record.

**What changed:** `docs/prd/campaign-filter-atl-earned.md` created; the feature registered in
`.workflow-state.json` at `phase: prd / completed` with `active_feature` repointed to it
(previous state backed up alongside). The PRD carries a provenance banner naming the dead session.

**Cost:** the reconstruction is faithful to the answers but not to the unwritten prose — the
agent's final PRD wording is unrecoverable. Every file anchor was therefore re-verified against
the working tree before being written, rather than trusted from the transcript.

### Corrections folded in, both recorded so nobody re-derives them

- **The ATL "discriminator split" is false.** The `@explore` subagent reported that
  `atl_media_performance` carries two competing discriminators — `placement_type`
  (`012_create_atl_media_performance.sql:18`) and `media` (`:49`) — with report filters reading
  one and canonical ingest populating the other, which would have made this a data-service
  ticket and would have matched the ticket's symptom exactly.
  `orchestration/tasks/load_marts.py:1436` writes `ifNull(s.media, '') AS placement_type` and
  `:1481` writes `nullIf(s.media, '') AS media` — **both projected from the same staging column**,
  documented as a static rename in that file's own docstring at `:1266`. The casing follow-up also
  fails: `query.py:446` lowercases the column and `_bind_list` (`query.py:63`) lowercases and strips
  the bind side. **No data-service change is in that feature**, and NFR-3 of the PRD says so
  explicitly so a subagent cannot re-open one.
- **A chosen scope item resolved to a no-op.** Round-1 Q4 selected "also the campaigns list page"
  as a dashboard target. That page has **zero** media-type references — nothing ATL/Earned exists
  on it to display correctly or incorrectly. Recorded as an answered decision honoured by
  verification rather than by an edit, and carried into the PRD as open question Q-1 (should the
  list page *gain* per-channel badges — net-new, separate ticket) rather than silently dropped.

**Standing rule this establishes:** when a harness failure loses written output, check
`opencode.db` for the session's `part` rows before re-doing the work. Decisions recorded in a
`question` tool result are evidence; re-asking them is not a neutral act.
